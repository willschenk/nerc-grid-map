correctness work worth doing later. **Nothing here is committed work**, and this
list is intentionally scoped to *improving what already exists* — not adding new

## Agent handoff checklist

This backlog is for **correctness and data quality** on the existing map — not new
UI, filters, or interaction features.

- **Start from source files** — edit `src/data/nerc/*` and pipeline inputs; never
  hand-edit `public/nerc/*.json` (see [Validation](#validation-before-reporting-success)).
- **Read `docs/standards/name-shortest.md`** before any label or `name_shortest` change.
- **Preserve project-owner supplied codes** unless clear external evidence proves them
  wrong (`shortest_source: "user_provided"` wins over prettier guesses).
- **Keep confirmed fixes separate from research questions** — apply verified rows;
  do not retarget open backlog items without new evidence.
- **Queue uncertainty** — append to proposal/research CSVs or use
  **`docs/cursor-research-prompts.md`**; do not silently change source data.
- **Run the right validation commands** — [Validation before reporting success](#validation-before-reporting-success).
- **Report handoff facts** — exact files changed and exact commands run (pass/fail).
- **Stay in scope** — fix labels, aliases, data, and existing renderer behavior only.

## Validation before reporting success

Future agents must **run the checks that match what changed** and **report the
results** — not stop after editing one JSON file. See **`docs/build-pipeline.md`**
for what is source vs generated.

### Source vs generated (do not confuse them)

| Edit here (source) | Produced by build — read/QA only |
| --- | --- |
| `src/data/nerc/org-names.json` | `public/nerc/orgs.json` |
| `src/data/nerc/area-aliases.json` | `area_aliases[]` on each org in payloads |
| `src/data/nerc/geocoded-orgs.json`, `map-combines.json`, registry ingest | same |
| `src/lib/nerc/map/nerc-org-map.ts` (+ `.css`) | Astro site in `dist/` after `npm run build` |

- **`public/nerc/*.json` regenerated by `npm run nerc:build`** — expected; commit
  them only together with the source edits that caused the diff.
- **`public/nerc/*.json` hand-edited** — **not acceptable.** Fix the source file
  and rebuild.

### Commands

| Command | What it checks |
| --- | --- |
| `npm run nerc:build` | Regenerate `public/nerc/orgs.json`, `orgs-render.json`, `org-details.json`, basemap |
| `npm run nerc:qa` | Data quality: schema, coordinates, combines, duplicates, **area-code drift** (`validateMarketAreaAliases` in step 14b), etc. |
| `npm run nerc:payload-check` | Split payloads match renderer field lists (`RENDER_ORG_FIELDS`) |
| `npm run ux-check` | Label length, collisions, display-name invariants on render orgs |
| `npm run check` | Astro / TypeScript diagnostics (`src/`, including the map client) |
| `npm run build` | Full site build; **`prebuild` runs `nerc:build`** automatically |

### When to run what

**Source data changed** (`org-names.json`, `area-aliases.json`, geocoded orgs,
combines, ingest, enrich logic that affects payloads) — run the **full list in order**:

```bash
npm run nerc:build
npm run nerc:qa
npm run nerc:payload-check
npm run ux-check
npm run check
```

Name-only or area-code-only edits still use this full list: aliases flow through
build and QA; `ux-check` catches label regressions.

**Renderer or map CSS changed** (`nerc-org-map.ts`, `nerc-org-map.css`) with **no**
source data edits:

```bash
npm run build
npm run ux-check
npm run check
```

Add `npm run nerc:qa` if you also touched `MISO_CONTROL_AREA_CODES`, PJM zone
sets, or anything that assumes fresh payloads.

**Docs only** (`docs/**`, proposals CSVs, worklists) — **no build required.**

**Perf/CDP scripts** (`scripts/perf/*.mjs`) — run the script named in the task
after `npm run build` when the script serves `dist/`.

Do not report success until the applicable commands exit 0 (or document a known
pre-existing failure unrelated to your change).
